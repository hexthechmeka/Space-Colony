# 프론티어 아웃포스트 — 데이터 스키마 안내

레벨 디자인을 넘겨주실 때 이 구조에 맞춰 주시면 그대로 반영됩니다.
모든 수치는 `frontier-outpost.html` 상단 `const DATA = { ... }` 한 블록 안에만 있습니다.

## 1. 전역 규칙 `DATA.meta`

| 키 | 현재값 | 의미 |
|---|---|---|
| `startRes` | 고철 150 / 연료 60 / 합금 0 | 시작 자원 |
| `offlineCapH` | 8 | 오프라인 정산 상한(시간) |
| `baseSlots` | 2 | 동시 유지 가능한 전초기지 수 (격납고로 증가) |
| `prepSec` | 30 | 건설(준비) 시간 |
| `interWaveSec` | 8 | 웨이브 간 재정비 시간 |
| `threatMeanMin` | [–,16,12,9,6.5,5] | 위험도 1~5별 재공격 평균 간격(분) |
| `threatGraceMin` | 6 | 포위 후 상실까지 유예(분, 정찰로 연장) |
| `storeMinutes` | 20 | 저장고 용량 = 분당 생산량 × 이 값 |

## 2. 행성과 후보지 `DATA.planets[].sites[]`

```js
{ id:'r1', name:'폐선 잔해지', risk:1, tier:1, res:'scrap', rate:16,
  cost:{scrap:40}, waves:3 }
```

- `risk` 1~5 — 재공격 빈도
- `tier` 1~5 — 적 강도 배율(`DATA.tierMul`)과 웨이브 표 선택
- `res` / `rate` — 자원 종류와 분당 산출
- `cost` — 개척 건설비 · `waves` — 확보에 필요한 방어 웨이브 수
- 행성의 `warp` 값이 모선 항속 레벨 이하일 때만 항로 개방
- 한 후보지를 확보하면 같은 행성의 다음 후보지가 열립니다

## 3. 적 `DATA.enemies` / 웨이브 `DATA.waves`

적: `hp, spd, dmg, r(크기), drop` + 원거리형은 `ranged, range, fireRate, bulletSpd`
웨이브: 티어별 배열, 한 웨이브 = `[[적ID, 마리수, 스폰간격초], ...]`

```js
waves: { 1:[ [['raider',5,1.2]], [['raider',6,1.0],['scrapper',3,0.8]] ], ... }
```

`shipWaves` 는 모선 요격 이벤트 전용입니다.

## 4. 승무원 · 로드아웃

### 병과 `DATA.classes`
```js
assault: { name:'돌격병', hp:112, spd:94, pref:'shotgun', perk:'근접 피해 +15%', perkDmgNear:1.15 }
```
`pref` 는 선호 무기(장착 시 피해 ×`DATA.prefBonus`), `perk*` 는 병과 특성 계수입니다.

### 무기 `DATA.weapons`
`dmg, cd(발사간격), range, spd(탄속), spread, pellets, pierce, moveMul, tier(병기고 해금 레벨)`

### 보조 장비 `DATA.gears` — 해금형(수량 무제한)
`tier`(장구류 해금 레벨) + 효과 계수: `hp, spd, rate, range, spread, armor, regen`

### 탄약 `DATA.ammo` — 재고형(출격 시 대원당 1탄창 소모)
`dmg, spd, range, burn(화상 초당 피해), frag(파편 피해)` + `craft`(제작비).
`std`(표준탄)만 `infinite:true` 로 무제한입니다. 시작 재고는 `DATA.ammoStart`.

### 오퍼레이터 `DATA.operators` — 전장에 나가지 않는 모선 관제
`ability`(Space 능력), `passive`(상시 효과), `cd`, 그리고 타입별 수치(`dmg/radius/heal/repair/slow`).
`관제 강화` 연구 레벨이 위력 ×(1+0.35L), 재장전 ×(1−0.12L) 로 작용합니다.

### 인사 규칙 `DATA.personnel`
정원(거주구), 부상 회복 시간(의무실로 단축), 부상 상태 출격 시 체력 배율, 모집 비용, 이름 풀.
**전투 불능 → 부상**(시간 회복), **부상 상태에서 재차 전투 불능 → 전사**(명부에서 제거).
전원 전사 시에는 예비 인원 2명이 자동 충원되어 진행이 막히지 않습니다.

## 5. 업그레이드 `DATA.tech`

`ship` / `outpost` / `trooper` 세 계통. 항목마다 `max`, `cost(레벨)`, `desc(레벨)`.
효과 자체는 코드의 헬퍼(`drillMul`, `siloMul`, `relayEff`, `slotMax`, `graceMs`,
`coreMaxHp`, `dmgMul`, `unitHp`)에서 읽으므로, 계수만 바꾸시면 됩니다.

## 6. 현재 구현된 루프

편성(전투원 4 + 오퍼레이터 1 · 로드아웃) → 강하 → 준비시간에 포탑 배치 → 지정 웨이브 방어 → 확보 →
실시간·오프라인 자원 축적 → 위험도에 따른 재공격(포위 시 채굴 정지) →
방어 실패·방치 시 상실(재개척) → 모선 요격 이벤트 → 3계통 업그레이드

저장 키: `fo_save_v1`(진행), `fo_opt_v1`(설정). 저장소가 막힌 환경에서는
메모리 폴백으로 동작하며 상단에 상태를 표시합니다.

## 7. 화면 구성 (전부 캔버스 픽셀 UI)

논리 해상도 **640×360 고정(16:9)** 을 정수 배율로 확대하고, 남는 영역은 레터박스 처리합니다.
캔버스는 두 겹입니다 — 아래는 픽셀 아트용(`#px`, 확대 시 도트 유지), 위는 글자 전용
선명 레이어(`#ui`, 논리 좌표 그대로 쓰되 기기 해상도로 렌더). 그래서 도트는 각지고 한글은 또렷합니다.

| 씬 | 내용 |
|---|---|
| `bridge` | 별밭 + 정박 행성 + 개척 전함 도트 아트, 포위·요격 경보 카드, 하단 명령 바 |
| `starmap` (성계) | 2000×1120 월드 좌표계, 항성이 중앙. 마우스 홀드 팬 · 휠 4단 줌(0.32/0.5/0.75/1.1) · 확대 시 우상단 미니맵 · 항행 중 카메라 추적 |
| `starmap` (성간) | 최대 축소에서 한 번 더 축소하거나 좌하단 [성간 지도] 버튼을 누르면 화면 전체가 은하 지도로 교체됨. 성계 노드 클릭으로 복귀 |
| `planet` | 행성 지표 탑다운 맵 + 후보지 마커(개척/가동/포위/미탐사 아이콘), 선택 시 하단 정보 패널 |
| `tech` | 3계통 탭 + 항목 카드(픽셀 아이콘·레벨 핍·비용 버튼) |
| `crew` | 승무원 명부 / 출격 편성 겸용. 좌측 명부, 우측 분대 4 + 오퍼레이터 1 슬롯, 하단 로드아웃(주무기·보조장비·탄약) |
| `battle` | 전장 전체 화면, 상단 전황 바 / 하단 분대 카드·자동 전투·포탑 배치·궤도 포격 |

UI 요소는 즉시 모드입니다. `panel()`, `button()`, `bar()`, `icon()`, `text()` 를 그리는 순간
클릭 영역이 등록되므로, 화면을 바꾸려면 해당 씬 함수만 고치면 됩니다.
아이콘은 `ICONS` 의 7×7 도트 문자열이고, 새 업그레이드를 추가하면 같은 `id` 로 아이콘만 하나 그려 넣으면 됩니다.

## 8. 성간 지도 데이터 `DATA.galaxy`

성계 지도를 대체해 화면 전체에 표시되는 은하 지도입니다. 나선 팔은 `arms`(팔 개수)와
`spin`(감김 정도)으로 절차적으로 그려지고, 성계 목록은 아래 형식입니다.

```js
{ id:'karon', name:'카론 성단', x:0.36, y:0.35, warp:4, note:'항속 기관 Lv.4' }
```

`x`, `y` 는 화면 안의 비율 좌표(0~1), `current:true` 는 현재 작전 성계(클릭하면 성계 지도로 진입),
`warp` 는 필요한 항속 기관 레벨입니다. 새 성계를 추가하면 노드와 이름·해금 조건이 자동으로 붙습니다.
나중에 성계 간 이동을 붙일 때는 이 목록이 그대로 이동 대상 테이블이 됩니다.
