## 현재 구현

### 조작과 지형

- 우클릭은 분대 이동. 빈 곳 좌클릭 유지 시 선택 대원이 포인터 방향으로 사격한다. 포인터 거리는 사거리를 제한하지 않는다.
- 적 좌클릭은 분대 집중공격이다. 각 대원은 자신의 사거리와 차폐를 확인한다. 현재 위치에서 사격하며 자동 접근은 없다.
- `1~4` 또는 하단 버튼으로 대원을 선택한다.
- 스페이스는 선택 대원 중앙 정렬이다. 누르는 동안 계속 중앙에 유지하고 가장자리 스크롤을 억제한다.
- 분대는 완전히 같은 간격과 속도로 이동하거나 도착 즉시 정렬하지 않는다. 가까운 재명령은 기존 느슨한 배치를 유지한다.
- 기본 이동속도는 초당 `120.4` 좌표 단위로, 이전 `86`의 1.4배다. 무기별 감속, 가속, 도착 감속과 뒤처진 대원 대기는 유지한다.
- 경사로와 물체 가림은 발 위치를 기준으로 처리한다. 대원 그림 확대는 표시만 변경하며 이동 충돌 크기는 키우지 않았다.
- 자연물별 이동 충돌, 시야 차폐, 탄환 차폐를 분리한다. 보임/사격 가능, 보임/사격 불가, 보이지 않음의 세 상태를 검증한다.
- 미탐색은 검정, 탐색했으나 현재 시야가 없는 지형은 반투명 검정이다. 물체 자체 가시성과 바닥 안개를 별도로 처리한다.

### 무기

- 권총, PDW, 소총, 저격총, 샷건, 기관총, 빔 소총, 빔 저격총의 8종. 수치는 모두 조작감 검증용 임시값이다.
- 히트스캔으로 피해를 즉시 판정하고 탄궤적을 표시한다. 아군은 피해 및 사격 차폐 대상이 아니다.
- 일반 총기는 조준 숙련도와 무기 분산, 이동, 연사 누적으로 실제 탄도가 빗나간다. 별도의 명중률 주사위는 없다.
- 빔 무기는 무작위 탄퍼짐, 반동 누적 및 이동에 따른 추가 분산이 없다. 숙련도에 따른 조준 오차만 유지한다.
- 빔 저격은 0.5초 조준 후 1.25초 조사한다. 발사 순간 명중 여부를 고정한다. 맞으면 그 피해 대상을 흔들림 없이 추적하고, 빗나가면 처음 궤적을 유지하며 뒤늦게 다른 적을 맞히지 않는다.
- 일반 총기는 탄창/예비 탄약, 빔은 충전 게이지/예비 배터리 개수를 표시한다. 바닥나면 자동 교체하며 배터리 교체는 더 길다.
- 시연의 무기 선택 변경은 시험을 위해 탄약을 다시 채운다. 실제 함선 재고 소비 기능이 아니다.
- 현재 연사 간격: PDW 0.07초, 소총 0.12초, 기관총 0.065초, 빔 소총 0.1초.
- 최신 사거리/기본 분산: AR(소총) 550 / 0.035라디안, 기관단총 역할의 PDW 350 / 0.06라디안, 일반 저격총 700 / 0.006라디안. 빔 저격총은 사거리 520 그대로다. 집중공격은 분대가 발견한 표적에만 가능하므로 실제 자동 교전 거리는 시야에도 제한된다.
- 기관총의 기본 이동 배율은 0.78이고 이동 사격 중 추가 배율 0.28을 적용한다. 저격총류는 개인 시야를 늘리고 발견 정보를 공유한다.
- 저격총 대원을 선택하면 선택된 그 대원의 시야만 사거리까지 일시적으로 늘어난다(일반 저격총 700, 빔 저격총 520). 다른 대원을 선택하면 기존 개인 시야(480/500)로 돌아온다. 선택 변경은 정지 상태에서도 안개와 발견 정보의 캐시를 무효화한다. 이미 탐색한 지역의 기억은 유지되지만 현재 시야는 원래 범위로 줄어든다.
- 대원 표시 크기는 1.4배. 화면 기준 탄궤적 두께는 일반탄 2, 빔 3이다.

### 최근 성능 개선

- 광선마다 관련 영역의 장애물만 미리 추려 기존 세부 검사에 전달한다. 검사 규칙과 결과는 바꾸지 않았다.
- 동일한 출발 위치에서 4명 × 96개 시야 광선 계산을 10회 반복한 로컬 측정은 평균 약 24ms에서 약 4ms로 감소했다. 전체 프레임 속도 측정은 아니다.
- 안개 캔버스는 가로/세로 절반 해상도로 계산하고 확대 표시한다. 시야 경계의 부드러운 표현은 유지한다.
- 분대 시야 폴리곤의 흐림 처리를 묶고, 이동 경로선도 하나의 경로로 그린다.
- 적 발견 판정을 프레임 내 공유하고 미니맵 및 화면 정보 갱신은 100ms 간격으로 제한한다.
- 우클릭 유지 자체가 이동 명령을 매 프레임 새로 만드는 방식은 아니다. 스페이스와 우클릭 동시 유지의 실제 체감은 추가 확인이 필요하다.

## 아직 구현하지 않은 방향

- 태세별 자율 행동, 적 조우 시 제압 후 이동 재개, 제한된 추격과 대열 안 자율 위치 선정
- 다양한 적 행동과 인간형 적, 임무 종류별 전투 진행 및 본편 전투 모듈 이식
- 외골격/파워수트와 무모함에 따른 독단 행동, 개인별 고저차 통행 권한
- 새 메인 메뉴, 저장 슬롯, 시작/로드, 튜토리얼 및 스킵
- 회사 평가, 거점 이주, 자원 거래와 신규 고용 등의 새 경제 흐름
- 조합식 승무원 초상화 및 장비/부상별 상태 표시의 실제 게임 연동

### 세계관 및 장기 설계 요약

- 주인공은 빚을 진 함장으로, 초거대기업 하청의 자원 채취/판매업에 가깝다. 군대 시뮬레이터보다 우당탕탕 우주모험을 지향한다. 빚의 이유와 입사 배경은 튜토리얼에서 길게 설명하지 않는다.
- 회사 수도의 깔끔한 미래도시에서 좋은 함선과 정규군으로 교육을 받고, 실제로는 낡은 함선과 초기 4명 및 능력이 낮은 오퍼레이터를 받는다. 첫 출격 뒤 외곽 거점으로 이주한다.
- 돈과 회사 평가는 별개다. 진급은 좋은 거점/장비의 이용 권한을 열지만 구매에는 돈이 든다. 분기 할당량 미달은 경고, 벌금, 해고의 순서다.
- 저장은 함선에서만 한다. 출격 이후 복귀까지 저장하지 않는다.
- 출격은 1~4명이고 비출격 오퍼레이터를 별도 지정한다. 승무원 모집은 계약금 및 장비/보급/치료 비용 중심이다. 특별한 조우 대원과 일반 모집 대원 사이에 큰 등급 차이는 두지 않는다.
- 모듈 설치/채굴 방어가 주요 전투 유형이지만 섬멸 임무도 있다. 모듈 투하/설치 소음에 적이 몰려오는 설정이다.
- 지속 생산 시설, 함선 적재량, 지시 회수와 전투 회수를 계획했다. 고위험 시설은 장기 방치가 불가능하고 위협 시 포기할 수 있다.
- 정상 철수는 전부 회수한다. 업그레이드로 해금하는 긴급 포드는 평지 LZ에 호출하고 도착 뒤 최대 10초 후 출발한다. 범위 밖 대원은 버리고, 포드는 공격받지 않으며 위치 변경/재호출은 하지 않는다.
- 긴급 회수율 40/75/100%는 실제 탈출 시점의 채굴 자원과 소모품에 적용한다. 무거운 장비는 포드 등급별 회수 가능 여부가 따로 있다.
- 전투/중상/행동불능의 3단계 체력과 누적 한도 감소를 계획했다. 중상자는 느리게 따라오고 행동불능자는 운반한다. 치료 및 운반 중 감소는 멈추며 치료 후 전투 복귀한다. 사망 및 미회수에는 손실이 있다.
- 복귀 상태에 따라 입원한다. 의료실은 기본 2슬롯에서 최대 8슬롯으로 업그레이드하고 배정된 인원만 현실 시간으로 치료한다. 출격/이동과 분기 진행은 게임 달력으로 구분한다.
- 무기별 탄종 및 함선 탄약/의료/폭발물/보급 포드 재고를 소비하는 방향이다. 공유 보급은 해당 무기 사용 인원의 잔량이 균등해지도록 분배한다.
- 그래픽은 가로 화면의 저해상도 픽셀 아트. 거점은 배경+메뉴, 함선 메인 화면은 외형을 표시하고 브리지는 내부 배경으로 구분한다. 함선 외형은 구매한 종류에 따라 달라지고 일반 업그레이드로 바뀌지 않는다.

## 검증 현황

이번 선택 기반 저격총 시야 변경에서 `node tests/terrain-weapons.mjs`, `node tests/field-combat.mjs`, `node tests/field-map.mjs`, `node tests/field-fog.mjs`, 문법 검사 및 `git diff --check`가 통과했다. 선택/해제 시 사거리 경계와 비저격 무기의 시야 유지도 검증했다. 아래 목록은 이전 전투/성능 작업까지의 검증 기록이며 이번 변경에서 전체를 다시 실행한 것은 아니다.

최근 코드 변경에서 아래 집중 테스트와 `npm run build`가 통과했다.

```sh
node tests/field-ray-broadphase.mjs
node tests/field-combat.mjs
node tests/squad-movement.mjs
node tests/terrain-demo.mjs
node tests/terrain-weapons.mjs
node tests/terrain-occlusion.mjs
node tests/field-fog.mjs
node tests/field-map.mjs
node tests/field-camera-focus.mjs
node tests/field-camera-edge.mjs
npm run build
git diff --check
```

- 광선 검사 최적화는 시야/사격 600개를 기존 방식과 비교해 동일한 첫 충돌 위치 및 대상을 확인했다.
- 브라우저에서 확대된 대원과 안개 화면, 우클릭 이동 및 목적지 도착, 스페이스 입력 후 상태를 확인했고 콘솔 오류는 없었다. 두 입력을 동시에 길게 유지하는 검증은 하지 않았다.
- `npm test` 전체 성공을 주장하지 말 것. 이전 실행에서 Windows의 `spawn npx ENOENT` 문제가 있었으며 전체 실행기 수정은 이 작업에서 하지 않았다.
- `npm run build`는 본편 번들 검증이다. `lab/` 시연의 동작은 별도 집중 테스트와 브라우저 검증으로 확인한다.

## 다음 작업

- 일반탄이 긴 직선으로 보여 레이저처럼 느껴진다는 사용자 의견이 있다. 짧은 이동 예광탄과 총구 섬광, 판정용 점선 분리를 제안했지만 아직 구현하지 않았다. 이번 변경은 선택된 저격총 대원의 임시 시야 확대만 포함한다.

1. 사용자가 최신 시연에서 이동 중 및 스페이스/우클릭 동시 유지 체감을 확인하도록 한다. 버벅임이 남으면 경로 탐색, 안개 합성, 렌더링을 나눠 실제 병목을 측정한다.
2. 확대된 대원과 탄궤적의 가독성을 확인하고 필요하면 크기를 조정한다. 표시 확대와 이동 충돌 크기를 혼동하지 않는다.
3. 조작감이 정리되면 사용자와 태세별 자율 교전/이동 재개를 설계한다. 먼저 임의의 AI 규칙을 추가하지 않는다.
4. 본편 이식 전에 프로토타입의 확정 사항을 다시 정리한다.
